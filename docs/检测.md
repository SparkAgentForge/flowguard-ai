这个项目最适合落在一个非常具体的主场景：

> **固定工位上的人工装配质量闭环。**

不是监控整个工厂，也不是泛化理解任意生产视频，而是针对一个明确产品、一套明确 SOP、一个固定摄像头，判断一次装配是否完整，并将异常推进到返工和复核完成。

## 一、具体业务场景

假设工厂有一个“小型泵体端盖装配工位”。

工人需要完成以下步骤：

1. 扫描泵体二维码，确认工单和零件型号。
2. 在泵体槽位内安装绿色密封圈。
3. 放置端盖，使用扭矩扳手锁紧螺栓。
4. 检查完成后粘贴质检标签。

这个流程看起来简单，但漏装密封圈可能导致产品出厂后泄漏。传统管理方式通常依赖：

- 工人自检
- 纸质或电子勾选
- 质检员抽查
- 出现问题后人工回看监控
- 人工整理异常和返工记录

问题是：**“勾选完成”不等于“真的完成”，视频存在也不等于证据能被快速利用。**

SparkSOP 的作用是把原本分散的 SOP、视频、人工判断和返工记录连成一条闭环。

------

## 二、场景中的参与者

| 角色           | 负责什么         | 如何使用 Agent                               |
| -------------- | ---------------- | -------------------------------------------- |
| 工艺工程师     | 编写和维护 SOP   | 上传 SOP，确认系统生成的工序规则             |
| 一线操作员     | 执行装配和返工   | 提交装配视频，接收返工任务                   |
| 班组长         | 处理工序异常     | 查看证据，批准或调整纠正任务                 |
| 质检员         | 决定是否最终放行 | 查看复核报告并关闭异常                       |
| SparkSOP Agent | 串联整个流程     | 解析 SOP、分析视频、阻断异常、生成工单和报告 |

比赛 Demo 不需要真的接入工厂组织系统。四个角色可以由同一套界面的不同操作阶段表现。

------

## 三、使用前的准备阶段

### 1. 上传 SOP

工艺工程师上传一份 PDF：

```
泵体端盖装配作业指导书 V1.3
```

内容包括：

- 适用产品型号
- 操作步骤
- 步骤先后关系
- 必须使用的工具
- 哪些步骤不能跳过
- 异常时的处理方式
- 所需证据

Agent 不只是把 PDF 放进 RAG，而是将其转换成可执行规则：

```
扫码零件
   ↓
安装密封圈
   ↓
安装端盖并锁紧
   ↓
粘贴质检标签
```

同时生成门禁条件：

```
未扫码               → 阻断
未安装密封圈         → 高风险阻断
先锁紧再安装密封圈   → 顺序异常
未检测到质检标签     → 不允许结束工单
视觉证据不足         → 转人工复核
```

### 2. 人工确认规则

系统展示转换结果，工艺工程师需要确认：

- 步骤名称是否正确
- 是否允许重复
- 是否有可选步骤
- 哪些异常必须阻断
- 视频中应该看到什么证据

这一步非常重要，因为模型不能擅自把一份自然语言文档变成生产放行标准。

------

## 四、正常装配场景

操作员完成一次正常装配，并上传一段 30～60 秒的视频。

Agent 输出一条步骤时间线：

| 时间  | 识别事件             | 置信度 | 证据             |
| ----- | -------------------- | ------ | ---------------- |
| 00:03 | 扫描泵体二维码       | 0.96   | 扫码关键帧       |
| 00:09 | 拿取并放置绿色密封圈 | 0.91   | 密封圈入槽关键帧 |
| 00:18 | 放置端盖             | 0.95   | 端盖安装关键帧   |
| 00:24 | 使用扭矩扳手锁紧     | 0.89   | 工具操作关键帧   |
| 00:39 | 粘贴质检标签         | 0.94   | 最终成品关键帧   |

规则引擎检查：

```
步骤完整：是
步骤顺序：正确
必需证据：齐全
低置信度事件：无
阻断规则：未触发
```

最终状态：

```
VERIFIED
```

系统生成一份简短的完成记录，而不是再创建异常工单。

------

## 五、主演示场景：漏装密封圈

第二段视频故意表现一个异常流程：

1. 工人扫描泵体二维码。
2. 没有安装密封圈。
3. 直接放置端盖并锁紧。
4. 粘贴质检标签。

### 1. Agent 观察视频

视频模型输出：

```
00:03 扫描零件
00:14 放置端盖
00:20 使用扭矩扳手
00:35 粘贴质检标签
```

Agent 没有观察到“安装密封圈”。

### 2. 规则引擎判断

SOP 状态机要求：

```
scan_part
→ install_seal
→ place_cover
→ tighten_bolts
→ apply_label
```

实际事件是：

```
scan_part
→ install_cover
→ tighten_bolts
```

因此系统产生：

```
异常类型：MISSING_STEP
缺失步骤：install_seal
严重程度：HIGH
当前状态：BLOCKED
```

这里不能只输出“可能漏装密封圈”，而要展示完整证据：

- 扫码完成时的截图
- 端盖安装前的截图
- 端盖安装后的截图
- 两个事件之间的时间区间
- 被违反的 SOP 条款
- 当前模型置信度
- 为什么触发阻断

### 3. 系统停止业务流程

比赛版不需要真的控制产线，只要将本次工单状态变成：

```
BLOCKED - 禁止质检放行
```

这代表“软件层门禁”，不是物理控制机器。

------

## 六、候选原因分析场景

发现漏步后，系统不应直接断言“操作员粗心”，因为视频不能证明人的动机。

Agent 根据预定义的原因图给出候选原因：

| 候选原因         | 支持信息               | 缺失信息               | 建议检查                 |
| ---------------- | ---------------------- | ---------------------- | ------------------------ |
| 密封圈供料盒为空 | 视频中没有看到拿取动作 | 供料区域部分遮挡       | 检查工位余料             |
| 操作员跳过步骤   | 扫码后直接安装端盖     | 无法判断是否为有意跳过 | 询问操作员并检查作业记录 |
| 密封圈提前放置   | 视频开始前可能已安装   | 开始画面看不清槽位     | 拆检或查看更早视频       |
| 视觉识别失败     | 手部遮挡密封圈区域     | 缺少侧面视角           | 转人工查看关键帧         |

这一步体现了陈睿擅长的因果分析，但需要严谨地称为**候选原因排序**，不能称为自动根因定论。

------

## 七、纠正任务场景

班组长打开异常工单，看到：

```
异常：密封圈安装步骤缺失
风险：端盖密封失效
建议处理：拆卸检查
```

Agent 生成纠正任务：

1. 隔离当前装配件。
2. 拆卸端盖。
3. 人工确认是否存在密封圈。
4. 如果缺失，补装对应型号密封圈。
5. 按 SOP 重新安装并锁紧端盖。
6. 录制返工复核视频。
7. 由质检员确认后关闭工单。

班组长可以：

- 接受建议
- 修改任务
- 标记为误报
- 要求补充证据
- 指派人工复核

每次操作都进入审计记录。

------

## 八、返工复核场景

操作员按照纠正任务重新操作，并上传第二段视频。

Agent 再次生成时间线：

```
00:04 拆卸端盖
00:12 展示密封圈槽位
00:18 安装绿色密封圈
00:25 放置端盖
00:31 使用扭矩扳手锁紧
00:45 粘贴返工合格标签
```

系统检查：

```
原异常已纠正：是
必需步骤完整：是
顺序正确：是
证据完整：是
需要人工确认：是
```

质检员确认后，工单从：

```
BLOCKED
```

变成：

```
REWORK_VERIFIED
```

这样系统完成的不是一次识别，而是一个有状态的业务过程。

## 九、证据报告场景

Agent 最终生成报告，内容包括：

### 基本信息

- 工单编号
- 产品型号
- 零件二维码
- SOP 名称及版本
- 原始视频哈希
- 返工视频哈希
- 分析使用的模型和 Skill 版本

### 原始异常

- 原始步骤时间线
- 缺失步骤
- 违反的 SOP 条款
- 异常严重程度
- 关键证据截图

### 处理过程

- 候选原因
- 人工确认内容
- 纠正任务
- 执行人和确认时间
- 是否修改过 Agent 建议

### 复核结果

- 返工后步骤时间线
- 前后证据对比
- 最终规则校验结果
- 质检员确认记录
- 最终状态

这份报告才是 Agent 的主要交付物。

## 十、另一个重要场景：证据不足

第三段视频不故意漏步骤，而是用手或工具箱遮挡密封圈区域。

系统可能得到：

```
install_seal: confidence 0.41
```

这时不能判定“已安装”，也不能直接判定“未安装”。

正确行为是：

```
状态：REVIEW_REQUIRED
原因：关键步骤视觉证据不足
建议：人工查看 00:08-00:14，或补拍槽位近景
```

这个场景非常适合比赛演示，因为它证明 Agent 不会为了给出答案而强行判断。

------

## 十一、扭矩值如何处理

摄像头通常只能判断“使用了扭矩扳手”，无法可靠判断真实扭矩值。

因此需要明确两种能力：

### 仅视频模式

能够检查：

- 是否使用了正确工具
- 是否执行了锁紧动作
- 大致锁紧顺序
- 是否遗漏某个螺栓

不能声称检查了实际扭矩值。

### 视频加工具数据模式

如果电子扭矩扳手可以导出记录：

```
{
  "tool_id": "TW-03",
  "workpiece_id": "PUMP-1024",
  "torque_nm": 18.2,
  "timestamp": "2026-09-20T14:32:11+08:00"
}
```

Agent 可以将工具记录与视频事件、零件二维码关联起来，检查扭矩是否在 SOP 范围内。

比赛 MVP 可以用一份预先准备的模拟工具数据演示这种关联，但必须明确说明它是模拟接口，不要假装接入了真实工厂设备。

------

## 十二、最适合比赛的三段演示

建议准备三段严格受控的视频：

### 视频 A：正常流程

证明系统能够正确放行，而不是只会报错。

### 视频 B：漏装密封圈

证明系统能发现漏步、触发阻断、生成纠正任务，并完成返工复核。

### 视频 C：严重遮挡

证明系统知道什么时候不能下结论，会转入人工复核。

三段视频分别覆盖：

```
正确放行
异常阻断
不确定性处理
```

比演示十种识别能力更有说服力。

------

## 十三、这个场景的边界

比赛阶段应明确声明：

- 用于质量辅助和流程审计，不替代最终安全认证。
- 只支持已经配置的产品和 SOP。
- 只处理固定机位、受控光照的预录视频。
- 不识别人脸、身份、年龄、情绪或工作意图。
- 不自动处罚操作员。
- 不自动控制设备或产线。
- 不根据视频估算无法直接观察的物理参数。
- 高风险异常必须由人确认后关闭。

因此，这个项目最准确的场景定义是：

> **面向固定人工装配工位的本地多模态工序审计与异常闭环系统：将 SOP 变成可执行规则，从视频中提取证据，发现异常后创建纠正任务，并通过返工视频完成复核和证据归档。**
