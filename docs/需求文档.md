# FlowGuard AI 产品需求文档

> 文档版本：V0.1  
> 项目阶段：比赛 MVP  
> 关联场景说明：[检测.md](检测.md)

## 1. 产品定义

FlowGuard AI 是面向固定人工装配工位的多模态工序审计与异常闭环系统。

NVIDIA DeepStream SOP 负责从视频中识别操作步骤、漏步和乱序；FlowGuard AI 在其前后增加两层能力：

1. **检测前**：把 PDF、Word 等操作手册转换为结构化 SOP，经人工审核后发布为可执行规则。
2. **检测后**：把异常检测结果转换为证据、工单阻断、人工确认、返工任务、返工复核和归档报告。

系统不以“发现 FALSE”为终点，而以“异常被处理并留下完整审计证据”为终点。

## 2. 产品目标

- 降低人工整理 SOP 规则的工作量。
- 保证 AI 使用的规则经过人工确认，并能追溯到原始手册。
- 对装配视频形成步骤级时间线和证据。
- 对漏步、乱序和证据不足进行不同处理。
- 将异常推进到返工、复核、放行和归档。
- 为比赛演示提供一条稳定、可重复、可解释的业务闭环。

## 3. 用户角色

| 角色 | 主要职责 | 系统操作 |
| --- | --- | --- |
| 工艺工程师 | 维护操作手册和 SOP | 上传文档、审核 AI 提取结果、发布 SOP |
| 一线操作员 | 执行装配和返工 | 提交装配视频、接收返工任务、提交返工视频 |
| 班组长 | 确认和处理异常 | 查看证据、确认异常、调整并下发返工任务 |
| 质检员 | 最终复核和放行 | 审核返工结果、关闭工单、归档报告 |
| 系统管理员 | 维护基础配置 | 管理产品、工位、人员和通知方式 |

比赛 MVP 可以使用同一账号切换角色视角，不要求实现完整企业组织系统。

## 4. MVP 业务流程

```text
上传 PDF/DOCX
  → AI 提取结构化 SOP
  → 工艺工程师审核与修改
  → 发布 SOP 版本
  → 上传装配视频
  → 视频推理生成步骤时间线
  → 规则引擎判断
      ├─ 合格：生成完成记录并归档
      ├─ 异常：阻断工单并进入返工闭环
      └─ 证据不足：转人工复核，不自动定责
```

异常闭环：

```text
异常待确认
  → 班组长确认
  → 生成并下发返工任务
  → 操作员提交返工视频
  → AI 重新检测
  → 质检员复核放行
  → 最终报告归档
```

## 5. 功能需求

优先级说明：P0 为比赛必须完成，P1 为有余力时完成，P2 为后续能力。

### 5.1 文档导入与 SOP 提取

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| SOP-001 | P0 | 支持上传 PDF 和 DOCX 操作手册 | 文件可上传，系统记录文件名、哈希和上传时间 |
| SOP-002 | P0 | 提取产品、步骤、顺序、前置条件、关键工具、阻断规则和证据要求 | 输出符合统一 SOP 数据结构，可在界面展示 |
| SOP-003 | P0 | 每条规则关联原文出处 | 至少包含文件名和页码或段落编号 |
| SOP-004 | P0 | 支持人工修改 AI 提取结果 | 修改前后内容和操作者可追踪 |
| SOP-005 | P0 | 未经人工批准的 SOP 不得用于正式检测 | 草稿状态无法关联正式工单 |
| SOP-006 | P0 | 发布后生成不可变版本 | 修改已发布 SOP 时必须创建新版本 |
| SOP-007 | P1 | 扫描 PDF 使用 OCR 识别 | 普通中文扫描件可以得到可审核文本 |

### 5.2 SOP 人工审核

审核页同时显示原文和 AI 结构化结果，支持逐步确认。

每个步骤至少包含：

- 步骤编号和名称
- 是否必需
- 允许的前置步骤
- 是否允许重复
- 可接受的乱序范围
- 视频中应该出现的证据
- 未满足时的处理方式
- 原文出处

SOP 状态：

```text
DRAFT（草稿）
  → AI_EXTRACTED（AI 已提取）
  → IN_REVIEW（人工审核中）
  → APPROVED（已批准）
  → PUBLISHED（已发布）
  → RETIRED（已停用）
```

### 5.3 视频检测

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| DET-001 | P0 | 支持上传本地视频并发起检测 | 可查看任务进度和最终结果 |
| DET-002 | P0 | 展示步骤时间线 | 每个步骤包含起止时间、置信度和识别结果 |
| DET-003 | P0 | 检测漏步和顺序错误 | 使用已发布 SOP 进行判断 |
| DET-004 | P0 | 保存关键证据 | 异常包含视频时间段和至少一张关键帧 |
| DET-005 | P0 | 区分异常与证据不足 | 低置信度或遮挡不得自动判定为操作错误 |
| DET-006 | P0 | 支持模拟推理结果 | NVIDIA GPU 服务不可用时，前后端仍可完成演示和联调 |
| DET-007 | P1 | 支持 RTSP 或工业相机 | 实时视频可以持续产生检测事件 |

### 5.4 异常分析与确认

异常详情必须分开显示：

- **已观察事实**：模型看到了什么、没有看到什么。
- **违反规则**：违反了哪个 SOP 版本的哪条规则。
- **候选原因**：AI 推测的可能原因，不作为最终事实。
- **人工结论**：班组长最终确认结果和备注。

系统禁止把“未检测到”直接描述为“操作员一定没有执行”。

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| AUD-001 | P0 | 异常自动阻断当前工单 | 工单不能直接进入完成状态 |
| AUD-002 | P0 | 显示异常证据包 | 包含 SOP 条款、视频片段、关键帧和模型置信度 |
| AUD-003 | P0 | 班组长确认、驳回或转人工复核 | 每次决定记录人员、时间和理由 |
| AUD-004 | P1 | AI 生成候选原因 | 明确标注为推测，并允许人工修改 |

### 5.5 通知与返工

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| RWK-001 | P0 | 异常确认后生成返工任务 | 任务包含问题、证据、操作要求和负责人 |
| RWK-002 | P0 | 支持站内通知 | 被指派人可以看到未处理任务 |
| RWK-003 | P0 | 操作员上传返工视频 | 视频与原工单、原异常关联 |
| RWK-004 | P0 | 返工视频重新执行同一 SOP 检测 | 输出新的步骤时间线和复核结果 |
| RWK-005 | P0 | 质检员进行最终放行 | 未经质检确认不得关闭异常 |
| RWK-006 | P1 | 支持邮件或企业微信通知 | 通知失败可重试且不影响工单主流程 |

### 5.6 报告与归档

最终报告至少包含：

- 工单、产品和工位信息
- SOP 名称、版本和原始文档哈希
- 原始检测时间线
- 异常及其证据
- 班组长确认记录
- 返工任务和执行记录
- 返工视频哈希及复核时间线
- 质检员结论
- 全部关键操作的人员和时间

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| ARC-001 | P0 | 生成结构化 JSON 报告 | 可供系统查询和二次集成 |
| ARC-002 | P0 | 生成可下载的 PDF 报告 | 内容与系统记录一致 |
| ARC-003 | P0 | 报告归档后不可直接覆盖 | 更正时生成新版本并保留旧版本 |
| ARC-004 | P1 | 按工单、产品、日期和状态检索 | 查询结果可定位到完整证据链 |

## 6. 工单状态机

```text
CREATED
  → INSPECTING
  → VERIFIED ─────────────────────────────→ ARCHIVED
  → EXCEPTION_PENDING
      → MANUAL_REVIEW
      → EXCEPTION_CONFIRMED
          → REWORK_ASSIGNED
          → REWORK_SUBMITTED
          → REWORK_REVIEW
              → RELEASED ─────────────────→ ARCHIVED
              → REWORK_ASSIGNED（再次返工）
      → EXCEPTION_REJECTED ───────────────→ VERIFIED
```

任何非法跨状态操作都由后端拒绝，不能只依赖前端隐藏按钮。

## 7. 非功能需求

- **可追溯**：规则、模型、提示词、人工决定和报告都必须有版本。
- **可替换**：视频推理通过适配器接入，不让业务代码依赖某个模型实现。
- **可演示**：GPU 服务不可用时，模拟服务可完整走通业务闭环。
- **幂等**：重复提交同一个推理回调或通知，不得重复创建异常和返工任务。
- **安全**：文档和视频默认私有；下载需要鉴权；日志不记录文件正文和访问令牌。
- **可观测**：每个请求使用统一追踪编号，可查询解析、推理、通知和归档状态。
- **性能目标**：除 AI 处理任务外，常规页面和接口在比赛环境中 2 秒内返回。

## 8. MVP 不做的内容

- 不控制真实生产线 PLC 或机械设备。
- 不承诺理解任意产品和任意拍摄角度。
- 不自动批准 AI 生成的 SOP。
- 不把 AI 候选原因作为人员责任认定。
- 不实现复杂企业组织、排班和多租户计费。
- 不在第一版同时支持多种视频推理框架。

- C 不等待 B 完成模型调优，先使用约定的模拟推理结果开发完整闭环。
- B 不依赖 C 的页面进行调优，使用固定测试视频和统一结果结构独立验证。

## 11. 比赛验收场景

1. **正常视频**：步骤完整，工单通过并生成完成记录。
2. **漏装视频**：发现第 2 步缺失，展示证据，阻断工单，完成返工和归档。
3. **遮挡视频**：系统判断证据不足并转人工复核，不武断认定漏装。
4. **SOP 导入**：上传操作手册，AI 提取步骤，人工修正一处错误后发布新版本。

主演示文案：

> 第 2 步未检测到，这是对应视频证据和 SOP 条款。本工单已阻断，班组长已确认，返工任务已下发。返工视频复核通过，最终报告已归档。
